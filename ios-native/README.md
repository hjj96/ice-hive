# Ледяной Улей 2.0 — нативная версия (Swift + SpriteKit)

Нативный порт веб-игры (three.js, папка `game/`) на Swift + SpriteKit. Веб-версия — эталон и спецификация:
тот же геймплей, тот же русский интерфейс, тот же визуальный стиль.

## Сборка на Mac

```bash
brew install xcodegen
cd ios-native
xcodegen generate
open IceHive.xcodeproj
```

В Xcode: таргет **IceHive** → *Signing & Capabilities* → выберите свою **Team**, затем запустите на iPhone или симуляторе (⌘R).

Проект `IceHive.xcodeproj` генерируется из `project.yml` и в git не хранится — после изменения `project.yml`
или добавления файлов снова выполните `xcodegen generate`.

Аргументы запуска (Edit Scheme → Run → Arguments):

| Аргумент | Что делает |
|---|---|
| `-demo combat` | миссия штурмовиком, отряд неуязвим, автопилот, 600 жуков вокруг — их число держится около 600 |
| `-demo beacon` | миссия, отряд у маяка «Альфа», толпа жуков |
| `-demo title` | титульный экран (за ним — станция в режиме демонстрации) |
| `-demo calm` | начало миссии без жуков (режиссёр выключен): освещение и вид станции |
| `-demo smoke` | то же, что `combat` |
| `-demo probe` | `combat` + составляющие «орды» по одной раз в 4 с (оверлей, баннер, тряска, звуки, вибро, орда) |
| `-demo hold` / `-demo extract` | маяки пропущены, отряд держится на лифте; `extract` — лифт поднимается и застывает на +2 с (пятна и трупы на платформе едут вверх) |
| `-demo levelup` / `-demo pause` / `-demo end` | карты улучшений / меню паузы / отчёт миссии (через 1.5 с) |
| `-seconds N` | через N секунд после окончания загрузки пишет в лог `demo done … avgFps=… minFps=… worstFrame=…` (первая секунда в статистику не входит) |
| `-debugHUD` | отладочная панель (fps, время симуляции и отрисовки, жуки на экране, частицы, узлы) |
| `-class assault\|pyro\|cryo\|gunner`, `-seed N`, `-mute`, `-orient portrait\|landscape` | класс, сид, без звука, фиксированная ориентация |
| `-nolight` | диагностика: без слоя темноты и фонарей |
| `-plainGlints` | диагностика: искры роя без шейдера (A/B его стоимости) |
| `-cull` | диагностика: включить собственное отсечение узлов SpriteKit (`shouldCullNonVisibleNodes`; по умолчанию выключено — пулы и чанки уровня прячут невидимое сами) |

Без `-demo` / `-debugHUD` сборка Release не пишет в stdout и не ведёт посекундный журнал (`hb`, `hitch`, `first`) —
только unified log (`os_log`).

## Настройки и рекорды

`UserDefaults` под ключами веб-версии `ledulei.<k>` (значения — JSON-текст, как в `localStorage`): `cls` (класс),
`best` (`{"kills":N,"win":S}` — рекорд убийств и лучшая эвакуация в секундах), `muted`, `vol` (0.2…1), `haptics`,
`quality` (`auto` / `low` / `med` / `high`). Версия 1.x (Capacitor, тот же bundle id) хранила их в Capacitor
Preferences = `UserDefaults.standard`, ключи `CapacitorStorage.ledulei.<k>`: при первом запуске 2.0 они копируются,
так что обновление сохраняет рекорд и настройки (`IceHiveCore/SettingsStore.swift`, тесты `SettingsStoreTests`).
Пауза: звук, громкость (100 → 80 → … → 20 %), графика (авто = средняя; низкая / средняя / высокая — лимит жуков
700 / 1400 / 2500 и плотность эффектов; на «высокой» на ProMotion — 120 Гц, пока устройство не греется и не включён
режим энергосбережения; иначе 60 Гц, под меню — 30 Гц), вибрация. iOS «Уменьшение движения» снижает тряску и отдачу
камеры до 35 % и удлиняет баннеры.

Управление: левая половина экрана — плавающий стик бега, правая — прицел и огонь, кнопки способности и рывка справа.
С клавиатуры (симулятор): WASD/стрелки — бег, IJKL — прицел и огонь, пробел — рывок, Q/E — способность, Esc — пауза.

## Структура

| Путь | Что это |
|---|---|
| `project.yml` | спецификация XcodeGen (iOS 16+, только iPhone, bundle id `com.hjj96.icehive`, версия 2.0.0) |
| `IceHiveCore/` | Swift-пакет с чистой игровой логикой (только Foundation + simd), тесты: `cd IceHiveCore && swift test` |
| `App/Sources/App/` | AppDelegate, SceneDelegate, `GameViewController` (SKView, клавиатура), аргументы запуска, лог |
| `App/Sources/Game/` | `GameScene` — единственная сцена: фиксированный шаг 60 Гц с аккумулятором, события ядра, режимы (титул / миссия / карты улучшений / пауза / отчёт); `DemoScript` — сценарии CI |
| `App/Sources/Render/` | `Iso` (ортопроекция 3/4 из манифеста, z-слои), `SpriteAssets` (листы спрайтов + манифест), `WorldRenderer` и слои `LevelLayer` (станция из тайлов), `BugLayer`, `MarineLayer`, `FxLayer` + `GroundFx` + `Particles` (эффекты, пятна, трупы, телеграфы), `LightingLayer` (темнота и фонари — SKShader), `CameraController` |
| `App/Sources/UI/` | HUD (счёт, задача, отряд, броня, кнопки, стики, баннеры, таблички над бойцами), экраны титула / улучшений / паузы / отчёта |
| `App/Sources/Input/` | двойные стики (мультитач) и клавиатура |
| `App/Sources/Audio/` | звук на AVAudioEngine (пул голосов + петли) по `Sounds/sounds-manifest.json`; после прерывания (звонок, Siri), смены маршрута (наушники) или сброса медиасервисов движок перезапускается |
| `App/Resources/` | `Sheets/` (пять листов спрайтов + `sheets.json`), `sprites-manifest.json`, `Assets.xcassets` (иконка), `Info.plist`, `PrivacyInfo.xcprivacy`, `LaunchScreen.storyboard`, шрифты, звуки |
| `art/Sprites/` | исходные кадры (`*.spriteatlas`, @2x/@3x) — результат `tools/render-sprites.mjs`, в приложение не входят |
| `tools/` | node-скрипты, которые пре-рендерят ассеты из веб-игры и пакуют листы (`pack-sheets.mjs`) |
| `ci/` | вспомогательные скрипты CI |

## CI

`.github/workflows/native-ios.yml` запускается на push в ветки `native*` (macOS-раннер GitHub): `swift test` для ядра,
сборка под симулятор, затем на симуляторе по очереди: `firstlaunch` (первый запуск после установки — кэш шейдеров Metal
ещё холодный, в первые ~20 с бывают подвисания по 100–500 мс; меряется отдельно), `-demo combat`, `beacon`, `title`, `calm`,
`combat` в альбомной ориентации, `combat -nolight` (без слоя темноты — для сравнения стоимости шейдера), `probe`
(составляющие «орды» по одной раз в 4 с — чтобы привязать подвисания к причине), `combat -cull` (A/B отсечения узлов
SpriteKit), `combat -plainGlints` (A/B шейдера искр), `hold` и `extract` (лифт), `levelup`, `pause`, `end` (экраны) со скриншотами. Приложение меряет fps `-seconds` секунд после строки `scene ready` (конец загрузки) и пишет
`demo done …`; скриншоты снимаются только после этого (`simctl io screenshot` на раннерах GitHub идёт 5–30 с и тормозит
GPU симулятора), имя `combat-6s.png` — через 6 с после `demo done`. Результаты коммитятся в ветку `ci-results` в папку
`<ветка>/<короткий sha>/` (`status.json`, `build.log`, `core-tests.log`, `bundle.txt`, `combat-0s.png` … `nolight-0s.png`,
`app-<демо>.log`, `fps.txt`, `loading.txt`, `hitches.txt` (кадры дольше 100 мс), `shots.txt`, `alive.txt`, `app.log`).
Строки `hitch` (кадр дольше 100 мс): `upd` — наш `update()` предыдущего кадра, `sk` — отрисовка и показ кадра
SpriteKit после него, `new` — сколько спрайтов пулам пришлось создать с прошлой такой строки (после загрузки должно быть 0).
Сборка в CI — конфигурация Debug, но с оптимизацией Swift (`SWIFT_OPTIMIZATION_LEVEL=-O`) и только arm64: так fps на
симуляторе ближе к реальному; отдельно собирается Release под устройство (`generic/platform=iOS`, без подписи) — её
ошибки и предупреждения в конце `build.log`. Ядро дополнительно гоняет `swift test -c release --filter PerformanceTests`
(строки `[perf]` в `core-perf.log`, на статус не влияет). Шаг «Privacy manifest check» проверяет, что каждый
API с обязательной причиной, который зовёт код (`systemUptime`, `UserDefaults`, …), объявлен в `PrivacyInfo.xcprivacy`.
В `hitches.txt` в конце — сколько раз SpriteKit писал `no drawables available` (пропуск кадра) в каждом демо. Строки `hb` в `app-<демо>.log` — fps, время симуляции/отрисовки, жуки, частицы, память;
`hb ms` — разбивка кадра по разделам (мс).

## Спрайты и отрисовка

Все кадры лежат в пяти листах `App/Resources/Sheets/sheet_*.png` (≈ 29 Мпикс, 111 МБ в памяти после декодирования;
на устройстве это память процесса, хотя `mem=` в логе симулятора её после загрузки не показывает — там текстуры живут
в GPU-процессе хоста),
сгруппированных по слою отрисовки: `bugs` (жуки, тени, трупы), `squad` (бойцы, пропы, ящики, фонари, перила),
`glow` (все аддитивные светящиеся слои), `level` (тайлы пола, юбки, опоры, фон), `fx` (плоские текстуры и частицы).
Кадры в @2x (свечение `glow` — в @1x: мягкий аддитивный свет, при сжатии берётся самый яркий из 2 × 2 пикселей,
так что искры роя не пропадают) и обрезаны по видимым пикселям; `sheets.json` хранит прямоугольник кадра в листе и его смещение в полном
кадре, поэтому якоря и размеры из `sprites-manifest.json` работают без изменений (`SKSpriteNode.show`).
Спрайты одного листа с одинаковым `zPosition` SpriteKit рисует одним вызовом: жуки и предметы на палубе
округляют глубину до целых слоёв (`ZBand.slice`), полы — до шагов по 0.25 м высоты.
Загрузка прячет всё за непрозрачной заставкой: листы декодируются в фоне (`SKTexture.preload`), все пулы спрайтов
(жуки, частицы, трассеры, пятна, трупы — ≈ 5 тыс. скрытых узлов) создаются заранее, а несколько кадров под заставкой
рисуются все эффекты и оверлеи по разу и сетка `PipelineWarmup` (каждый лист × режим смешивания × `colorBlendFactor` ×
прозрачность) — чтобы SpriteKit собрал конвейеры Metal до первого видимого кадра (иначе при холодном кэше шейдеров,
в первый запуск после установки, каждый новый конвейер подвешивает кадр на 100–600 мс).
После изменения кадров: `node ios-native/tools/render-sprites.mjs` (сам вызывает `pack-sheets.mjs`) или только
переупаковка: `node ios-native/tools/pack-sheets.mjs`.

Темнота — один полноэкранный спрайт с `SKShader` (`LightingLayer`), умножающий картинку на карту света: окружение
≈ 0.27/0.32/0.43 яркости заранее освещённых спрайтов, конусы четырёх фонарей и до шести точечных источников
(вспышки, огнемёт, напалм, маяк). Настройки сверены со скриншотами веб-версии того же места.
Кадры тел жуков `pack-sheets.mjs` пакует с «плёночным» подъёмом яркости (≈ ×4.5 в тёмных тонах, света мягко
сворачиваются): запечённые под полный свет, под умножением темноты они становились чёрными. Слой искр рисует шейдер,
который мягко расширяет каждую искру и усиливает её; разброс яркости по жукам — как у веб-версии (0.55…1.3), поэтому
искры ярких жуков уходят в белый (сверено с `store/…/2-swarm.png`).
