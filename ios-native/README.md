# Ледяной Улей 2.0 — нативная версия (Swift + Metal)

Нативный порт веб-игры (three.js, папка `game/`) на Swift: мир рисует собственный Metal-рендерер из настоящих
3D-мешей веб-версии, интерфейс (HUD, меню, заставка) — SpriteKit-сцена, которую `SKRenderer` рисует в тот же
Metal-проход. Веб-версия — эталон и спецификация: тот же геймплей, тот же русский интерфейс, тот же визуальный стиль.

## Сборка на Mac

```bash
brew install xcodegen
cd ios-native
echo 'DEVELOPMENT_TEAM = ABCDE12345' > Local.xcconfig   # один раз: id своей команды (файл в .gitignore)
xcodegen generate
open IceHive.xcodeproj
```

Подпись берётся из `Local.xcconfig` (его подключает `Signing.xcconfig`), поэтому `xcodegen generate` её не сбрасывает.
Схемы: **IceHive** (Debug, с проверкой Metal API — для разработки) и **IceHive Release** (Release без проверки
Metal API — для замеров на устройстве и скриншотов магазина). Архив для App Store: схема IceHive → *Any iOS Device* →
Product → Archive.

Проект `IceHive.xcodeproj` генерируется из `project.yml` и в git не хранится — после изменения `project.yml`
или добавления файлов снова выполните `xcodegen generate`.

Аргументы запуска (Edit Scheme → Run → Arguments):

| Аргумент | Что делает |
|---|---|

| `-demo beacon` | миссия, отряд у маяка «Альфа», толпа жуков |
| `-demo title` | титульный экран (за ним — станция в режиме демонстрации) |
| `-demo calm` | начало миссии без жуков (режиссёр выключен): освещение и вид станции; в CI — базовая линия (без нагрузки) |
| `-demo layout` | как `calm`; через 1 с каждый экран раскладывается и проверяется на четырёх телефонах в горизонтали (874 × 402, 932 × 430, 844 × 390, 667 × 375 со своими safe area): `layout ok\|FAIL …`, итог `layout sizes: 40 ok, 0 FAIL on 4 phones` (см. «LAND «Горизонталь»») |
| `-demo smoke` | то же, что `combat` |
| `-demo probe` | `combat` + составляющие «орды» по одной раз в 4 с (оверлей, баннер, тряска, звуки, вибро, орда) |
| `-demo hold` / `-demo extract` | маяки пропущены, отряд держится на лифте; `extract` — лифт поднимается и застывает на +2 с (пятна и трупы на платформе едут вверх) |
| `-demo queen` | как `hold`, и сразу поднимается Матка (v1.1, 1 000 000 HP или `-queenHp N` — остаётся на платформе для скриншота) |
| `-demo queenlock` | `queen`, и через 3 с отсчёт лифта кончается при живой Матке: «Лифт заблокирован — Матка жива» |
| `-demo holdhint` | как `hold`, но отсчёт лифта держится в первых 8 с удержания: подсказка контура уровня («Контур бьёт каждые 6 с — …») остаётся на экране — в две строки на телефоне |
| `-demo coach` | первая миссия на чистом профиле демо: идёт «Учебная высадка» (без автопилота — шаги сменяются по таймаутам), через 2.5 с время почти останавливается (×0.02) для скриншота; `-coachStep N` — сразу шаг N (0–4) |
| `-demo pressure` | Ветеран, никто не трогает экран: перемотка до 26 с (`-pressure red`, «Рой стягивается») или 15.5 с (`-pressure amber`, «Улей просыпается»), давление держится в этой полосе |
| `-demo report` | отчёт миссии по образцу (`-report first\|win\|loss\|chip`, спецификация §3): исход миссии задаётся через 1.5 с и записывается в профиль демо в памяти |
| `-demo levelup` / `-demo pause` / `-demo end` | карты улучшений / меню паузы / отчёт миссии (через 1.5 с) |
| `-demo swarmshot` | момент скриншота App Store `2-swarm` (`harness/scenarios/store-shots.mjs`, кадр b): пулемётчик, 12 с миссии, отряд на переходе (0, −5), несколько шагов, 600 жуков вокруг, огонь вверх-влево 1.6 с, затем время почти остановлено (×0.02); графика «высокая», как у скриншотов магазина — сверка с `store/screenshots/6.3/2-swarm.png` |
| `-seconds N` | через N секунд после окончания загрузки пишет в лог `demo done …` (первые 1.2 с в статистику не входят) |
| `-debugHUD` | отладочная панель (fps, время симуляции и мира, кодирование, GPU, жуки на экране, частицы, вызовы) |
| `-class assault\|pyro\|cryo\|gunner`, `-seed N`, `-mute`, `-orient left\|right` | класс, сид, без звука, одна сторона горизонтали (`right` — Dynamic Island слева; без аргумента — обе) |
| `-bugs N` | `combat` / `beacon`: число жуков (не больше лимита уровня графики) |
| `-mscale N` | масштаб картинки мира (пиксели на точку, по умолчанию 2 — как pixel ratio веб-версии на «высокой»; экран iPhone — 3, интерфейс всегда в родном масштабе экрана) |
| `-glintDots` | каждая искра роя дорисовывается сглаженной точкой (по умолчанию выключено — как в веб-версии) |
| `-storeShot` | без отладочной панели даже в Debug (скриншоты магазина) |
| `-failMetal` | проверка: вести себя так, будто Metal не запустился (сообщение вместо бесконечной заставки) |
| `-tier 0\|1\|2` | уровень миссии (Новобранец / Ветеран / Кошмар); в демо по умолчанию — Ветеран, на титуле — как выбор игрока |
| `-coach 0\|1` | «Учебная высадка» в миссии да / нет (по умолчанию — правило первой миссии) |
| `-queen`, `-queenHp N` | Матка в начале удержания; её здоровье |
| `-profile fresh\|returning\|veteran` | профиль демо (в памяти, ничего не пишется): новый игрок или вернувшийся (6 вылетов, 3 эвакуации, штурмовик — Сержант с нашивками Н·В) |
| `-station N` | станция по сиду — только с флагом сгенерированных станций (`AppFeatures.generatedStations`, пока выключен: пишется в лог и игнорируется) |
| `-layoutCheck` | в лог — прямоугольник каждого элемента титула / HUD (через 1 с миссии) / паузы / карт улучшений / отчёта, затем `layout ok` или `layout FAIL` с перекрытиями, выходами за безопасную зону и зонами касания меньше 44 pt |

Без `-demo` / `-debugHUD` сборка Release не пишет в stdout и не ведёт посекундный журнал (`hb`, `hitch`, `first`) —
только unified log (`os_log`).

## Настройки и рекорды

`UserDefaults` под ключами веб-версии `ledulei.<k>` (значения — JSON-текст, как в `localStorage`): `cls` (класс),
`best` (`{"kills":N,"win":S}` — рекорд убийств и лучшая эвакуация в секундах), `muted`, `vol` (0.2…1), `haptics`,
`quality` (`auto` / `low` / `med` / `high`). Версия 1.x (Capacitor, тот же bundle id) хранила их в Capacitor
Preferences = `UserDefaults.standard`, ключи `CapacitorStorage.ledulei.<k>`: при первом запуске 2.0 копируется каждый
такой ключ, которого ещё нет под `ledulei.<k>` (и те, что 2.0 пока не читает, — например, профиль более поздней 1.x),
так что обновление сохраняет рекорд и настройки (`IceHiveCore/SettingsStore.swift`, тесты `SettingsStoreTests`).
Пауза: звук, громкость (100 → 80 → … → 20 %), графика (авто = средняя; низкая / средняя / высокая — лимит жуков
700 / 1400 / 2500, плотность эффектов, тень от фонаря игрока на «высокой»; на «высокой» на ProMotion — 120 Гц, пока
устройство не греется и не включён режим энергосбережения; иначе 60 Гц, под меню — 30 Гц; при перегреве `.serious` —
эффекты не выше средних, без тени, картинка мира 1.5x, при `.critical` ещё и 30 Гц), вибрация. iOS «Уменьшение движения» снижает тряску и отдачу
камеры до 35 % и удлиняет баннеры.

Только горизонтальная ориентация (обе стороны). Управление: левая половина экрана — плавающий стик бега, правая —
прицел и огонь, «Рывок» и способность — дугой вокруг кольца прицела у правого края.
С клавиатуры (симулятор): WASD/стрелки — бег, IJKL — прицел и огонь, пробел — рывок, Q/E — способность, Esc — пауза.

## v1.1 «Ставки» — ядро

Правила веб-версии v1.1 (ветки `origin/v1.1/*` — только для чтения; откалиброванные числа — `a-threat` 8e95162)
перенесены в `IceHiveCore` по спецификации порта. Всё, что решает игра и что читает игрок (тексты задачи, подсказки,
отчёт, звания), строит ядро, и тесты закрепляют это дословно; приложение пока только рисует Матку — HUD-состояния
угрозы, карточка «Учебной высадки», выбор уровня на титуле и новый отчёт — работа UI-пакета.

- **Уровни** (`Tuning.swift`, `Difficulty`): Новобранец / Ветеран / Кошмар — строки веб-таблицы DIFF без изменений
  (Ветеран: ручеёк ×1.25, подъём с 45 % брони; Кошмар: ручеёк ×1.2, Матка 6000 HP), `GameConfig.difficulty` по умолчанию —
  Ветеран; `Difficulty.override` меняет поля по веб-именам (`trickle`, `qHp`, …). Скрытая строка `legacyV10` — ровно v1.0
  (без Матки, давления и часов застоя; бегуны растут с HP): по ней сверяется порт и гоняется регрессия v1.0. Уровень миссии:
  выбор игрока (`diff`), иначе Новобранец до первой эвакуации, потом Ветеран (`effectiveTier`).
- **Режиссёр**: множитель орды внутри `startHorde` (двойное округление, как в вебе), орда первого маяка у «Учебной
  высадки» ×0.65, лимит особых жуков — сравнение с дробным `(cap + 2·маяки)·specCap`, часы застоя (`stallTime`: громилы и
  без прогресса задачи), защита импульса лифта при `pulse = 0`, спад импульса к краю. Бегуны — 15 HP ×0.88…1.12 на любом
  уровне в любой момент (одна пуля штурмовика); остальные жуки растут с `hpMul`.
- **Давление улья и AFK** (`GameDirector`, `GameThreat.swift`): пока ни один маяк не запущен (или отряд тянет с
  подъёмом к лифту), растут часы `pressure`; с `grace − 10` с — «Улей просыпается» (жёлтый), с `grace` — «Рой стягивается»
  (красный, сердцебиение раз в 1.2 с игрового времени), дальше ручеёк и часы орд ускоряются до ×4, а с ×1.5 чётные uid
  охотятся на игрока. 12 с без ввода (не на автопилоте) — две трети роя идут на игрока. **Дорога к лифту** (решение
  натива, веб не менялся): после третьего маяка часы стоят, пока не выйдет запас на дорогу — путь от игрока до лифта по
  полю задачи на полной скорости (5.3 м/с) ×1.3 + 5 с (`liftAllowance`, меряется, когда поле задачи впервые смотрит на
  лифт). Раньше часы шли с «Лифт вызван»: у автопилота, который идёт прямо к лифту (медиана 22 с у Ветерана, 25 с у
  Кошмара), жёлтый был в 61 из 61 миссии Ветерана, красный — в 19 из 61 и в 20 из 20 у Кошмара; теперь 1 / 0 из 62 и 2 / 1
  из 20. Тот, кто стоит, после запаса будится как у маяков (жёлтый через 15 с у Ветерана).
- **«Графика» и рой** (решение натива): размер орд больше не следует за лимитом графики — `hordeScale()` = 1 (веб:
  `min(1, cap/1400)`, «низкая» с лимитом 700 делила каждую орду пополам, и Ветеран выигрывал 94 % вместо 70–85 %, Кошмар —
  41 % вместо ≤ 30 %, при полном ×1.5 очков и нашивках). Низкий лимит теперь только ограничивает живой рой (лишние жуки
  орды не появляются, пока рой на лимите). Лимит миссии фиксируется при старте (`GameConfig.quality`): «Графика» из паузы
  сразу меняет эффекты, тени, масштаб и 120 Гц, а размер роя — со следующей миссии. Справочные строки гейта на «низкой»
  (те же сиды, что первые 8 на класс): Ветеран 88 % (парные на средней — 78 %), Кошмар 25 % (22 %); на сидах 2000 —
  72 % / 72 % и 25 % / 16 %.
- **Матка** (`GameQueen.swift`): через 35 / 35 / 30 с зачтённого удержания — 2 с красного кольца у дальнего края лифта,
  потом она взбирается: экземпляр громилы (радиус 1.5, масштаб 4.2, HP `qHp·hpMul`), выводок, залп кислоты по каждому
  стоящему бойцу в 18 м, таран по своим часам, укус ×1.6, ярость ниже половины HP (×1.35 скорость + орда). Не замерзает,
  холод ≤ 0.5, импульс лифта и морозные взрывы её не трогают. Пока она жива, орды удержания стоят, ручеёк ×0.4/0.6, а лифт
  не уйдёт (`liftLocked`, «Лифт заблокирован — Матка жива»); смерть — взрыв 8 м / 300, две аптечки, +60 опыта,
  `.queenKilled`, через 4.6 с эвакуация. `debugSkip()` в удержании сначала убирает её.
- **Источники урона и падения** (`DamageSource`): последний удар по игроку объясняет падение (`downs`, `downBy` — для
  отчёта), плюс счётчики урона и падений отряда по источникам для калибровки.
- **«Учебная высадка»** (`GameCoach.swift`): пять шагов (бег, прицел, способность, рывок, маяк), каждый — по действию
  или по таймауту 7 / 12 / 9 / 8 с; пока идут шаги 1–4, рой молчит (`calm`), боты не стреляют, пока на них давят меньше
  двух жуков; `.coachSeen` после шага 4, «Пропустить» или раннего выхода на маяк. Строка «{имя} ранен — встаньте рядом,
  чтобы поднять» — один раз за миссию в первых трёх вылетах. Тексты карточки — `CoachText`.
- **Профиль, очки, звания, нашивки, отчёт** (`Profile.swift`): профиль v1 (JSON в ключе `profile`), очки только за то,
  что делает игрок, ×0.8 / ×1.0 / ×1.5, выслуга = очки/10, 10 званий по классу, нашивки Н·В·К, совет по причине
  поражения, «дольше прошлой попытки», цель. `MissionReport.make` собирает все строки отчёта.
- **Хранение** (`SettingsStore`): новые ключи `profile`, `diff`, `tut`, `sticks`, `seed`; профиль игрока v1.0 (2.0 или
  Capacitor 1.x) строится из `best` (эвакуация → Ветеран) и пишется только при следующем отчёте; битые значения → по
  умолчанию (и числа вне диапазона `Int`: `sticks` = `1e20` раньше ронял запуск в `Int(Double)`). Демо (`SettingsStore(volatileMeta:)`, `MetaFixture`) держат эти ключи в памяти и ничего не пишут.
- **Генератор станций** (`Stations.swift`): побитовый порт `genLevel / genCheck` веба (`e-stations` ffeeea7), seed 0 —
  «Кельвин-9»; тесты сверяют золотые векторы веба (1000 сидов валидны, тур p10/p50/p90 = 207/252/301). Рисовать
  сгенерированные станции будет WP6 — до тех пор приложение играет «Кельвин-9».
- **Отладка** (`GameDebug.swift`): `debugQueen(hp:)`, `debugSetPressure`, `debugSetLiftTime`, `debugHurt`,
  `debugCoachStep`, `debugSetOutcome`, `debugSetRun`, `threatDebug`, `coachDebug`; в `debugState` — уровень, станция,
  угроза, давление, Матка.

В приложении v1.1 пока только: Матку рисует меш громилы ×4.2 с фиолетовым тоном (одна строка в `WorldSwarm.build`),
`-demo queen`, сброс задержки hit-stop на `.queenKilled`, звук `queen.wav` (отрисован `tools/render-audio.mjs` из
копии дерева с `09-audio.js` / `12-main.js` ветки `a-threat`; остальные WAV при повторной отрисовке совпадают с точностью
±1 младшего бита — их не трогали).

### Калибровка

`icehive-calib` (`IceHiveCore/Sources/IceHiveCalib`, логика — `Calibration.swift`) играет миссии без отрисовки: автопилот
(`auto`), автопилот без урона и способности (`passive`), без ввода (`afk`, 420 с), автопилот до первого маяка (`afkbeacon`);
средняя графика (лимит 1400), первая карта улучшения. Сид прогона k = `seed0 + 10000·режим + 1000·уровень + 100·класс + k`,
результаты детерминированы. Строки JSONL — в именах полей веб-`run.mjs` (веб-`agg.mjs` читает нативные строки и наоборот).

```bash
cd IceHiveCore
swift run -c release icehive-calib --preset gate --jobs 3 --out calib.jsonl --summary calib.txt --gate
swift run -c release icehive-calib --tiers 1 --n 8 --th '{"trickle":1.3}' --tag t13 --out t.jsonl   # перебор
swift run -c release icehive-calib --agg calib.jsonl web.jsonl                                       # только сводка
```

Пресеты: `gate` (CI: Новобранец 4×8, Ветеран 4×16, Кошмар 4×8, AFK Ветеран и Новобранец по 4, passive 4, legacy 4×2,
справочно Ветеран и Кошмар 4×8 на «низкой» графике — `--q low`, теги `vet-qlow` / `nm-qlow`, в гейт не входят),
`full` (40 на класс и уровень + AFK + passive; в CI — `workflow_dispatch` с `calib: full`), `stations` (сгенерированные
станции 0–4, справочно), `legacy`. Порог гейта (шаг «Calibration gate» в `core-tests`, файлы `calib.txt` / `calib.jsonl`
в результатах; «downs» — падения всего отряда за миссию):

### v1.1 «Ставки» — интерфейс

Приложение читает состояния ядра и только раскладывает их (все строки — из ядра, кроме подписей кнопок):

- **Миссия.** Уровень — `settings.effectiveTier` при каждом старте («В бой», «Ещё раз», «Обучение», фишка отчёта); первая
  миссия на свете (`isFirstMission`) идёт с «Учебной высадкой»; строка «{имя} ранен — …» — в первых трёх вылетах. В конце
  миссии забег один раз записывается в профиль (`Profile.commit` + `saveProfile`; сдача — поражение), повышение звания —
  вибро `.success` через 0.65 с. Все демо работают на профиле в памяти (`SettingsStore(volatileMeta:)`, `DemoFixtures`):
  CI не зависит от сохранённого профиля симулятора и не меняет его.
- **HUD угрозы.** Блок задачи в четырёх видах: обычный; «Улей просыпается» (жёлтая кромка, жёлтые подпись, текст и
  полоса давления); «Рой стягивается» (тёмно-красная заливка, красная кромка и текст, полоса пульсирует 1 ↔ 0.45 за 0.6 с,
  маркер цели красный и дышит 1 ↔ 1.3); Матка (фиолетовая кромка, полоса её потерянного здоровья — фиолетовый → красный),
  «Лифт заблокирован — Матка жива». Текст и вид меняются только со сменой состояния (ключ задачи включает угрозу и
  блокировку лифта). Reduce Motion — без пульсаций.
- **«Учебная высадка».** Карточка под блоком задачи: «N/5», текст шага (сенсорный или клавиатурный вариант — по
  последнему вводу), «ПРОПУСТИТЬ» (зона ≥ 44 × 44, тап как у меню — работает, пока палец держит стик); длинный текст
  делится на две строки по « — » (без переносимых меток). Призрачный палец на настоящем элементе (после поворота
  на другую сторону или смены safe area переезжает вместе со стиками и кнопками): на стиках — петля
  перетаскивания 1.6 с, на способности и рывке — нажатие 1.1 с и янтарное кольцо кнопки 0.9 с; на шаге маяка — кольцо
  вокруг маркера. Всё на времени стены, только позиции / масштаб / прозрачность (Reduce Motion — петли по 3 с). Пока
  карточка видна, тосты — под ней; карточка не шире промежутка между колонкой строк отряда и правым краем
  (`HUD.coachMaxWidth`). Подсказка управления первых 7 с — только без «Высадки».
- **Телефонный HUD (VX-5).** Строки отряда — только у бойца, который упал, у кого < 35 % брони или чья табличка за
  экраном / под блоком задачи (свою строку игрок не видит); после 6 с работы стиками (ключ `sticks`) стики в покое — 0.16
  без подписей; свечение орды ×0.7; стрелка маркера не заходит в блок кнопок способности и рывка (+20 pt) —
  останавливается на его границе. Таблички над бойцами (VX-2) не переносились: их заменят дуги брони WP4.
- **Подсказка в две строки.** Подсказка шире промежутка между кольцами стиков (минус 24 pt; 334 pt на 874, 219 pt на 667)
  делится на две строки, как #hHint в вебе: по « · » или « — » (тире остаётся в первой строке), иначе по пробелу у
  середины; растёт вверх от своей нижней строки (сразу над блоком брони); половина, которая всё ещё не влезает (SE),
  уменьшает обе строки. Так идут подсказки контура Ветерана / Кошмара (~450 pt одной строкой) и строки «{имя} ранен — …»
  (~370 pt). Две однострочные метки того же стиля, что и прогретая подсказка; ширина меряется
  `NSAttributedString.size()` только при смене текста. Демо `holdhint` держит отсчёт лифта в первых 8 с удержания.
- **Камера** — см. «LAND «Горизонталь»»: упреждение вдоль длинной оси экрана, отъезд в толпе (`CameraController.zoom`:
  1.10 при > 240 жуков у цели, 1.0 при < 180, сглаживание 1.2 с⁻¹) применяется в `MetalCamera` (передача M2 закрыта).
- **Титул.** Строка профиля вместо рекорда («Штурмовик · Сержант · рекорд 9 120» / «Вылетов: N · эвакуаций: M»), на
  карточках классов с вылетами — «ЗВ. N» и нашивки Н·В·К, под карточками — «СЛОЖНОСТЬ» и три сегмента (≥ 44 pt; выбранный —
  бирюзовая рамка 2 pt, у Кошмара красная) со строкой уровня; одно касание — выбор (`diff`). Вводный абзац — только до
  первого вылета. На низком экране раскладка по шагам убирает подсказку управления, потом абзац, потом ужимается.
  Ряд уровня — в одну строку.
- **Пауза.** «ПАУЗА · ВЕТЕРАН» и две колонки кнопок по 44 pt: миссия (Продолжить, Обучение, Сдаться — под ними
  подсказка управления) и настройки (Звук, Громкость, Графика, Вибрация); «Обучение» — та же миссия заново с
  «Высадкой» (брошенная миссия не записывается). «Графика» меняет картинку сразу, размер роя — со следующей миссии.
- **Зоны касания ≥ 44 pt.** Кнопки меню (`MenuButton.hitRect`) и сегменты уровня на титуле на низком экране рисуются
  34–40 pt, но ловят касание в зоне не меньше 44 × 44; когда зоны соседних кнопок перекрываются, побеждает кнопка, к
  нарисованному краю которой касание ближе. `-layoutCheck` проверяет каждую зону (`small tap … → layout FAIL`).
- **Отчёт.** `MissionReport` ядра в две колонки (A: метка, заголовок, подзаголовок, полоса этапов МАЯК·МАЯК·МАЯК·ЛИФТ·
  МАТКА·ЭВАКУАЦИЯ, «ОЧКИ» с «НОВЫЙ РЕКОРД» / «рекорд N», разбивка и строка уровня «×0,8», мини-числа; B: звание класса с
  полосой выслуги и «НОВОЕ ЗВАНИЕ», нашивка, советы — причина поражения, «дольше прошлой попытки», переход на Ветерана,
  фишка «Попробуйте «Новобранец»», цель, кнопки): колонки рядом, кнопки над сгибом, без подзаголовка (как в вебе на
  телефоне в горизонтали). Не помещается — плотнее шрифты и отступы, потом только первый совет. В конце миссии отчёт строится по кадру на шаг (`MenuScreen.beginEnd` / `stepEnd`: колонка A,
  колонка B с проверкой высоты, раскладка — экран появляется с ней, ~0.05 с: шаги идут при 60 Гц, 30 Гц меню включаются с последним шагом, а не в тике конца миссии, где уже лежат события конца, профиль и модель отчёта): весь отчёт за один кадр стоил
  63–74 мс на CI. Дороже всего оказалась рамка: растр размером с коробку (×3) на каждую новую высоту отчёта — 15–37 мс
  на шаге раскладки; рамки паузы и отчёта теперь 9-slice маленькой кэшированной текстуры (`Shapes.panelStretch`: углы со
  срезом не масштабируются). Смена размера экрана и прогрев строят отчёт сразу (`showEnd`). Лог: `report built in N frames:
  a / b / c ms`, `end tick: profile + report model … ms, menu reset … ms` (и события тика дольше 3 мс).
- **Демо и порог кадров.** Новые состояния меняются внутри окна порога (с 1.2 с после «scene ready»), чтобы их первый
  кадр мерился: отчёт / пауза / level-up / сдача — через 2 с после «scene ready», Матка — через 2 с (блокировка лифта
  у `queenlock` — ещё через 1.5 с), «Высадка» — следующий шаг через 1.5 с, `pressure` — жёлтый до 1.5 с, потом красный.
  Раньше всё это случалось в первую секунду, которую порог не считает.
- **Прогрев под заставкой.** HUD рисует по разу все новые строки задачи в их цветах и размерах, варианты панели и полосы,
  подсказки удержания, строки «ранен», карточку, палец, кольца, красный маркер; меню — паузу с «Обучением» и отчёт дважды
  (победа с рекордом, нашивкой и званием; поражение с советами и фишкой); `TextWarmup` — строки уровней, советы, цели и
  подзаголовки отчёта на ширинах колонок.
- **Лог** (CI ищет): `v11 start tier= coach= station= seed=`, `v11 title tier= runs= pick=`, `v11 threat N`, `v11 queen
  warn|spawn|enrage|kill`, `v11 lift locked`, `v11 coach step=|seen|end`, `v11 run tier= won= … rank=a→b medal= recTip=`.

## LAND «Горизонталь» — только горизонтальная ориентация

Владелец: «игра должна быть в горизонтальной ориентации, постоянные лучи у героев … скорее мешают». Отсюда:

- **Только горизонталь.** `Info.plist` — `UISupportedInterfaceOrientations` = landscape right + left (right первой: с ней
  запускается, Dynamic Island / вырез слева), `UIRequiresFullScreen`; `GameViewController.supportedInterfaceOrientations` =
  `.landscape` (`-orient left|right` закрепляет одну сторону — так CI получает одинаковые снимки), предпочтительная —
  landscape right; экран запуска — горизонтальный. Портретных веток раскладки нет: каждый экран — одна горизонтальная
  раскладка. Лог: `scene presented size=874x402 iface=landscapeRight`. Сцена всегда появляется на первой стороне из
  `Info.plist`; с `-orient left` система затем переворачивает её (размер тот же, `view resized` нет) — поэтому
  `viewDidAppear` сразу просит закреплённую сторону (`requestGeometryUpdate`), поворот пишется в лог по его окончании
  (`interface rotated iface=landscapeLeft size=874x402`), а через 1 с после появления — сторона, на которой интерфейс
  остался (`interface settled iface=…`). `ci/upright.sh` поворачивает снимок по **последней** стороне в логе.
- **HUD** (`UI/HUD.swift`, `HUD.Geo`). Верхний ряд: счёт / время / комбо слева, задача по центру между ними и паузой
  (44 × 44, касание 60 × 60) справа. Под ним: строки отряда — колонка слева, карточка «Высадки» — по центру (не шире
  промежутка до колонки отряда), тосты — колонка справа, не ниже кнопки «Рывок» (старые уходят). Низ: блок брони
  (260 pt, по центру, 8 pt над нижней safe-зоной); кольца стиков на высоте больших пальцев (центр 124 pt над нижней
  safe-зоной — круги кончаются над блоком брони): движение — 100 pt от левой safe-кромки, прицел — 168 pt от правой;
  «Рывок» (r 31) и способность (r 39) — дугой вокруг кольца прицела у правого края (выше-правее и ниже-правее, ≈ 125 pt
  от его центра); подсказка — нижней строкой в 15 pt над блоком брони, растёт вверх; по центру над бронёй, если её
  строки помещаются между кольцами (по 12 pt до каждого), иначе ближе к середине промежутка. Баннер — на 30 % высоты,
  заголовок `clamp(30, 13 % высоты, 52)`. Таблички над бойцами (`Nameplates`) при наложении встают одна над другой:
  табличка бота — на 26 pt над соседней, табличка игрока (под полосой брони у неё штрихи магазина) — на 31 pt, у
  лежащего бойца ещё +4 pt (полоса подъёма), так что штрихи не наезжают на имя под ними; таблички перекрываются, если их
  центры ближе полусуммы ширин + 6 pt (76 / 96 pt), а у верхнего ряда расходятся вбок на столько же. Под меню (пауза,
  карты улучшений, отчёт) подсказка и тосты не показываются (`HUD.covered`): раньше они выглядывали между картами и
  над рамкой отчёта.
- **Титул**: логотип через верх (его строка не заходит на строку «ОПЕРАЦИЯ …»: отступ растёт с размером логотипа),
  четыре карточки классов в ряд, ряд уровня в одну строку, подсказка и строка профиля слева от «Звук» / «В БОЙ»; на
  телефоне повыше лишняя высота (до 60 pt) расходится между блоками, а не остаётся тёмной полосой внизу. Камера
  титула ставит отряд на свободное место справа от логотипа (NDC 0.5, 0.52: луч через эту точку экрана пересекает
  палубу в точке `g` — камера смотрит на `f − (g − f)`, и отряд стоит там при любом покачивании). **Пауза** — две колонки (миссия / настройки), **карты улучшений** — блок по центру safe-зоны, высота
  карт по самому длинному описанию, **отчёт** — две колонки; `-failMetal` и заставка — по центру.
- **Камера** (`MetalCamera`, `CameraController`): fov 40°, над и под точкой взгляда видно 10.8 м — у каждого телефона
  одна глубина (≈ 26 м палубы сверху вниз), шире телефон — больше по бокам (874 × 402: ≈ 47 м); упреждение прицела
  вдоль длинной оси экрана — 3.6 м вбок, 1.5 м в глубину; точка взгляда на 2.4 м к низу экрана (игрок чуть выше
  центра — в свободной полосе между верхним рядом и большими пальцами); отъезд в толпе ×1.10 применяется (M2);
  эвакуация — прежний отъезд ×1.35 с подъёмом наклона.
- **Без постоянных лазеров** (`FX/MetalEffects.sights`). Длинных цветных линий от стволов больше нет (ни у игрока, ни

## Как строится кадр

**Цикл.** `FrameLoop` владеет единственным `CAMetalLayer` (корневой вид `GameView`) и своим `CADisplayLink`
(30 / 60 / 120 Гц через `preferredFrameRateRange`). Каждый тик:

1. берёт слот кадра и drawable **без ожидания** (на GPU не больше двух кадров, арен загрузки — три). `nextDrawable()`
   ждёт, пока композитор вернёт картинку, — до секунды (CI 26ae6ea: 381 мс на главном потоке при простаивающем GPU),
   поэтому `DrawableSource` спрашивает drawable в фоновой очереди в тот момент, когда у тика есть слот, и ждёт ответа
   не дольше 3 мс (свободный drawable отдаётся за микросекунды). Не успел — тик не рисует, а вызов ждёт дальше в
   очереди, и его drawable достаётся следующему тику. Заранее запрошенный запасной drawable стоил бы кадра конвейера, а
   очередь, стоящая в `nextDrawable()`, пока главный поток делает `present`, задерживала его (CI a108d1d: `drawn` в
   `combat` 58 → 33, подвисания 55–229 мс в `draw`); `addPresentedHandler`, по которому можно было бы считать
   drawable'ы, в SDK симулятора нет. Нет свободного слота (GPU не успевает) или drawable (композитор не вернул) — тик только считает:
   симуляция, ввод, HUD, звук и вибро идут в своём темпе, на экране остаётся прошлая картинка, а время эффектов
   копится (`dtCarry`) и отдаётся следующему нарисованному кадру;
2. `SKRenderer.update` → `GameScene.update`: симуляция ядра, события, камера, `MetalWorld.update` (камера всегда;
   позы отряда, инстансы роя с отсечением по пирамиде, эффекты, свет и загрузка в арену — только когда слот есть;
   под меню мир не пересобирается, пока камера стоит), HUD, звук;
3. один command buffer: проходы ниже, `present` (ниже частоты панели — в целевое время тика display link'а, чтобы
   60 Гц на ProMotion и 30 Гц под меню шли ровно), учёт времени буфера (`GPUTimeline`: коммит → запуск → готово, время GPU).

**Контракт вывода.** Материалы считают линейную яркость и отдают её через `encodeColor()` / `encodeMultiply()` из
`Shaders/Common.h`: туман exp² подмешивается в линейном пространстве (цвет тумана — линейная яркость), тонмаппинг,
грейд и sRGB — один раз в композите. Поэтому сложение вспышек и частиц идёт в яркости, и ядро взрыва сходит в
тональную кривую градиентом, а не обрезается в плоский диск. Экспозиция — сценарная, без автоэкспозиции:
`PostChain.exposureEV` = EV настроения (`Resources/Look/exposure.json`, когда появится) + EV кадра (кинематографические
планы) + короткий провал после большого взрыва (`dip`). Грейд — `Resources/Grade/<настроение>.lut` (сырые 32³ RGBA8),
пока их нет — встроенный «gameplay»: нейтрально-холодный, с глубоким чёрным (точка чёрного 4 %), мягкой S-кривой,
холодными тенями и чуть тёплыми светами, насыщенность ниже в глубоких тенях и выше в средних тонах; блум плотный
(порог 0.8, сила 0.3, каждый следующий, более широкий уровень весит 0.6 предыдущего), виньетка и зерно лёгкие. `PostChain.brightness` — гамма для опции «Яркость»
(сама опция в настройках — у владельца меню). Для снимков look-dev: `-brightness G` (0.5–2) и `-exposure EV` (EV кадра,
−4…4).

**Свет и воздух** (WP2, `Lighting/*`, `Shaders/Lighting.h`, `Shaders/Atmosphere.metal`). Дисциплина света смеси
«Кристалл + тьма хоррора»: окружение — слабый холодный лунный свет (полусфера 0.68, луна 0.9 — чуть выше веба: в
линейном HDR через ACES и «носок» грейда это тёмно-синяя палуба; вдвое меньше — палуба тонет в чёрном и сливается с
пустотой), свет дают четыре фонаря отряда, короткие источники сетки и холодная подсветка над отрядом (читаемость в
темноте). Фонарь — около половины вебовской силы (34 игрок / 23 отряд против 62 / 42: в линейном HDR старые значения
клали пятно на плечо тоновой кривой, плоский бледный клин), свет в воздухе несут лучи. Затухание «приплюснутое» 1 / (1 +
(d / 4 м)²), нормированное к вебовскому d^−1.35 на 5 м (ближняя зона ≈ 0.6 — жук у ствола и боец в чужом луче не
выгорают), «куки» прожектора: горячее ядро, слабое тёмное кольцо, кольцо отражателя у края, мягкий край. Пустота за
уровнем — глубокий тёмно-синий «Кристалла» (после грейда ≈ (15, 30, 58), в кадре с дымкой ≈ (18, 35, 62)), бездна под
палубами темнее (≈ (9, 21, 42)) — почти чёрные опоры стоят силуэтами, тьма — в неосвещённых конструкциях, а не в пустоте; цвета тумана задаются экранным значением и переводятся в линейную яркость
бисекцией (`LightGrid.radiance(display:)` — сходится и у самых тёмных значений). `Lighting.h` — модель света для всех
материалов на двух уровнях. *Только кадр* (`lambertLight`, `standardLight`, `spotShadow` — сигнатуры прежние,
материалы до WP2 работают без правок): полусфера + луна + 4 фонаря + 3 точечных (`LightGrid` кладёт в них свет
эффектов, подсветку отряда и самый сильный источник сетки) + тень фонаря игрока из атласа. *Полный* (`LIGHTING_PARAMS`
в сигнатуре фрагментной функции, `shadeLit(LIGHTING_ARGS, поверхность, high)` и `heightFog`): плюс сетка XZ 16 × 16
ячеек по 3 м вокруг игрока с 32-битной маской источников (≤ 32: дульные вспышки каждого бойца, огнемёт, криолуч,
напалм, вспышки взрывов из пятен света эффектов, маяки, лампы станции — их регистрирует модуль уровня через
`LightingHub.setStationLamps`, иначе они читаются из старого `level_glow.mesh`; CPU-биннинг), тени всех четырёх
фонарей из атласа (4 выборки PCF), окружение из зонда 64² (Карис EnvBRDF + верхний мип как рассеянный), лак (clear
coat, только High), контактная тень из карты занятости и высотный туман бездны. Буфер `LightBlock` и текстуры (атлас —
слот 3, зонд — 4, занятость — 5) привязываются один раз за кадр на весь проход мира (непрозрачный элемент 10). Воздух:
объёмные конусы — аналитический вход / выход луча из конуса, обрезка плоскостью палубы под бойцом (без чтения глубины
— MSAA не мешает), фаза Хеньи–Гринстейна, дрейфующая пыль, в воздухе затухание мягче, чем у пятна на полу (с крутой
игровой камеры луч лежит над своим пятном и должен пережить его, чтобы читаться), яркая сердцевина вдоль оси (луч, а
не широкий веер дымки), насыщение на луч (вуаль, не засветка); на High конус игрока — 8 шагов через его тайл атласа (жуки и бойцы режут луч), остальные — 3 шага. Снег
(High 5000 / Efficient 1800 / «низкая» 900 хлопьев в коробке 24 × 24 × 6 м вокруг отряда) и низкий туман светятся
только в лучах — аддитивно, без окружения: без фонарей погода не добавляет ничего (`-nolight`: в CI кадр со снегом и
без него отличается на 0.1 уровня яркости). В бездне — 2 слоя дрейфующего тёмного тумана (Efficient — 1), дымка — лишь
мягкий подъём цвета бездны в глубине шахты (без прежнего светло-голубого «пола»), красные и натриевые огни на опорах
(часть мигает), туман по глубине ниже палубы лифта. Зонд окружения — `Resources/Env/station_probe.ihe` (64² RGBA16F, 5
мипов GGX, 0.26 МБ) печётся в Blender / Cycles: `tools/blender/env/bake_probe.py` (сцена только из излучающих
поверхностей — освещённые поверхности «предосвещены», поэтому два запуска дают одинаковый md5). Оценки iPhone 12 (±50
%, не измерены): атлас ≤ 0.45 мс High / ≤ 0.15 Efficient, конусы ≤ 0.6 / ≤ 0.25, занятость ≤ 0.05, сетка ≤ +0.3 мс при
32 источниках. Для замеров на устройстве (разница в `hb gpu world=` / `shadow=`): `-nocones`, `-noweather`, `-noatlas`
(только тайл игрока), `-lights off` (без сетки), `-nolight` (без фонарей и источников). Раз в секунду — строка `hb
light lights=… cells=… tiles=… beams=… [march] occ=… tier=…`. Замер в CI (кадры без HUD, полоса мира y 700–1900,
коммит с сердцевиной лучей): swarmshot — медиана яркости 39 (цель смеси 35–50; до WP2 48, с первой дисциплиной света
30), p95 / p50 5.3, R−B светов +54 / теней −26, клип 0.44 %, почти чёрного 18 %; маяк — 32 (добавит EV настроения
«beacon» у WP7), спокойный кадр — 43; центры пятен фонарей — максимум канала 224 (< 250); погода без фонарей — +0.004
уровня.

**Качество и разрешение** (`Frame/RenderQuality.swift`). «Высокая» → High (DRS 1.5–2.0 px/pt, блум ½ × 5, искажение;
бюджет iPhone 12 при 1400 жуках ≤ 10.5 мс GPU обычно / ≤ 11.5 пик), «средняя» → Efficient (1.2–1.6 px/pt, блум ¼ × 4;
≤ 6.5 / 7.0 мс), «низкая» → Efficient с полом 1.2 px/pt. Оценки бюджета прохода WP1 на iPhone 12 (`stress1400`):
MSAA + резолв ≈ 0.6 мс, блум ≈ 0.45 мс, финал ≈ 0.8 мс (≤ 1.9 мс вместе), ±50 % — **ни одна цифра не измерена на
устройстве**; время GPU симулятора (CI) — только сигнализация о патологиях. Цель мира выделяется один раз под размер,
который просит `FrameLoop` (масштаб мира `GameScene`), и растёт только при повороте или большем `-mscale`; динамическое
разрешение двигает вьюпорт (регулятор по сглаженному времени GPU к 11.5 мс при 60 Гц, 6.8 мс при 120 Гц, 7.0 мс у
Efficient). Термолестница с гистерезисом 30 с: nominal — выбранный уровень, 120 Гц разрешены; fair — 60 Гц до конца
миссии и пол DRS + 0.1; serious — Efficient + DRS; critical — Efficient на 1.2 px/pt (30 Гц — только последний шаг;
сейчас его включает `GameScene`). 120 Гц — только ProMotion, «высокая», nominal, без энергосбережения и при сглаженном
GPU ≤ 6.5 мс 2 с; после 3 с DRS на полу — до конца миссии 60 Гц. Предел жуков по классу устройства (отдельно от
уровня графики): A13 и старше 900, A14 1400, A15 / A16 1800, A17 Pro и новее 2500 (`RenderQuality.deviceBugCap`;
применяет ядро — запрос владельцу `Tuning`). `-mscale N` фиксирует масштаб; `-drsSweep` (и демо `probe` в CI) делает
10 шагов DRS между краями диапазона раз в 2 с, чтобы показать, что шаг не стоит подвисания.

**Измерение GPU** (`Frame/GPUCounters.swift`). На устройстве (выборка счётчиков на границах стадий) каждый проход
рендерера несёт отметки времени начала и конца в `MTLCounterSampleBuffer` кадра; раз в секунду строка
`hb gpu frame=… max=… shadow=… world=… bloom=… final≈… | ema=… tier=… scale=… range=… view=… alloc=… allocs=…
thermal=… 120hz=… bugcap=… ev=…` (финальный проход открывает `FrameLoop` — пока он не подключает буфер выборок,
`final≈` — остаток кадра). В симуляторе счётчиков нет: только время command buffer'а целиком.

**Куда расти.** Новые форматы вершин (скиннинг, текстуры вершинной анимации) — новый `VertexLayout` (свой
`MTLVertexDescriptor`) + свои вершинные функции; модуль объявляет `PipelineSpec` (мир — MSAA 4x и HDR автоматически,
`.depthOnly` для теней, `.distortion` для тепловых спрайтов) и регистрирует элементы стадий с ключом порядка. Варианты
по уровню — функциональные константы: `PipelineSpec.world(…, tiered: true)` компилирует конвейер дважды (`<метка>.high`
/ `<метка>.efficient`, константа `FC_TIER_HIGH` = индекс 0), модуль рисует `renderer.tieredPipeline(метка)(renderer.frameTier)`;
в шейдере — `TIER_CONSTANT(kИмяHigh);` из `Common.h` один раз на файл (имя своё в каждом файле) и `if (kИмяHigh) { … }`
(ветка вырезается в каждом варианте). Так сделан композит (`kPostHigh`: искажение только у «высокой»). Каждый такой
конвейер — вторая компиляция под заставкой: только там, где уровни правда различаются. HUD остаётся последним
проходом в родном масштабе.

**Загрузка.** Меши, текстуры и все конвейеры (в CI сейчас 29: 24 мира, 5 поста) готовятся в фоне с момента `loadView` (`MetalPreload`), пока на
экране заставка; мир начинает рисоваться под ней, и заставка уходит, только когда GPU вернул ≥ 20 кадров мира, а все
оверлеи HUD, баннер, тосты, меню паузы, отчёт миссии, карты улучшений и каждый вид взрыва / смерти жука / заморозки /
кислоты отрисованы по разу (первые использования не стоят ничего в игре). Переносимый по строкам текст (`TextWarmup`:
все тосты, описания карт, абзацы экранов) раскладывается и рисуется один раз в фоне с `loadView` — первая такая
раскладка в процессе стоила в CI 1.5–9 с на первом двухстрочном тосте посреди миссии; сами двухстрочные тосты
(подсказки о новых жуках, «Вы ранены…») создаются под заставкой и потом переиспользуются.

**Текст HUD.** `SKLabelNode` рендерит новую текстуру на каждую новую строку, и в симуляторе это ждёт GPU хоста, когда
тот стоит. Поэтому часто меняющиеся числа (убито, время, комбо, броня, уровень, расстояние до цели, отладочная панель)
— `GlyphLabel`: моноширинный JetBrains Mono из атласа глифов, отрисованного один раз (`GlyphAtlas`); новое значение лишь
переставляет спрайты. Чтобы числа стояли ровно там, где их рисовал `SKLabelNode`, `GlyphCalibration` перед первым кадром
один раз рисует вне экрана (через `SKRenderer`, в масштабе экрана) эталонный `SKLabelNode` и `GlyphLabel` с одним и тем
же текстом для каждой используемой конфигурации (шрифт, размер, выравнивание, строк), читает пиксели и сдвигает
`GlyphLabel` на разницу их границ (целые пиксели; в логе — `glyph calibration …`). Атласы рисуются под заставкой.

**Текстуры HUD — только под заставкой.** Медленный `SKRenderer.render` в CI — почти целиком ожидание, а не работа
(`hud 339 (cpu 1)`): первая отрисовка новой текстуры (текст, картинка) в симуляторе ждёт хост. Поэтому под заставкой
рисуются все атласы глифов, все 48 текстур сектора перезарядки каждой кнопки, меню и тосты, а панели счёта и задачи —
одна текстура на высоту, растянутая по однородной середине (`Shapes.stretchedPanel`, девять частей `centerRect`), а не
новая на каждую ширину. Новые текстуры посреди миссии остались только у текста баннера, задачи и подсказки (несколько
раз за миссию; поле `labels=` в строке `hitch`).

**Сбой Metal.** Если Metal не запустился (нет устройства, библиотеки или обязательного конвейера) — вместо бесконечной
заставки сообщение «Не удалось запустить графику (Metal). Перезапустите игру.»

**Жизненный цикл.** В фоне display link на паузе (GPU-работы в фоне нет); при уходе в неактивное состояние игра
ставится на паузу; при нехватке памяти сбрасываются кэши текстур HUD и живые частицы (в лог — память до/после).

## CI

`.github/workflows/native-ios.yml` запускается на push в ветки `native*` (macOS-раннер GitHub): `swift test` для ядра,
сборка Debug под симулятор (с оптимизацией Swift `-O` и только arm64 — так fps ближе к реальному), архив Release
под устройство (`generic/platform=iOS`, без подписи) с проверкой того, что уходит в магазин (`release-check.txt`:
версия 2.0.0, имя, `ITSAppUsesNonExemptEncryption`, arm64, только горизонтальные ориентации и `UIRequiresFullScreen`,
иконка, манифест приватности, `default.metallib`, нет спрайтовых листов, размер), сборка Release под симулятор; затем на
симуляторе (iPhone 17 Pro, горизонталь 874 × 402, каждый запуск с `-orient right`, кроме `title-left`; каждый снимок
поворачивается `ci/upright.sh` по последней стороне в логе — `scene presented … iface=…`, затем `interface rotated|settled
iface=…`, — так что все PNG — горизонтальные картинки, а у `title-left` Dynamic Island справа) по очереди:
`firstlaunch` (первый запуск после установки — кэш шейдеров холодный; меряется отдельно), `combat`, `beacon`,
`swarmshot` (+ `swarmshot-dots`), `swarm` (1400 жуков) и `swarm3x` (мир в 3x), `calm` (базовая линия: без жуков и
событий — остаётся только хост), `title` (+ v1.1 `title-fresh`, `title-return`, `title-nm` — `-tier 2`:
выбран КОШМАР; `title-left` — другая сторона горизонтали, `-orient left`, снимок поворачивается в другую сторону), `layout` (каждый экран на четырёх телефонах, не в пороге кадров), `probe`, `hold`, `extract`, `holdhint`,
`queen`, `queenlock`, `coach`, `coach3`, `pressure`, `pressure-amber`, `levelup`, `pause` (+ `pause-nm` на Кошмаре), `end`,
`report-first`, `report-win`, `report-loss`, `report-chip` (строки `v11 …`, `layout ok` и `iface=landscape` проверяет шаг
«Verify»; список демо — `DEMOS` / `MENUS` в env задания), затем
`-failMetal` (должно появиться сообщение), Release без аргументов (stdout должен остаться пустым) и `release-combat`.
Приложение меряет кадры `-seconds` секунд после строки `scene ready` и пишет `demo done …`; скриншоты снимаются
только после этого (`simctl io screenshot` идёт 5–30 с и тормозит GPU симулятора). Результаты коммитятся в ветку
`ci-results` в папку `<ветка>/<короткий sha>/` (`status.json`, `build.log`, `release-check.txt`, `core-tests.log`,
`bundle.txt`, `metrics.txt`, `fps.txt`, `loading.txt`, `hitches.txt`, `shots.txt`, `alive.txt`, `app-<демо>.log`,
`<демо>-<с>s.png`, `app.log`, `other-phones.txt`). Шаг «Layout check on the other landscape phones» — те же экраны
(титул, HUD с подсказкой контура и с «Высадкой», пауза, карты, отчёт) с `-layoutCheck` на iPhone SE (667 × 375),
iPhone 16e (844 × 390) и iPhone 16 Plus (932 × 430), если рантайм их предлагает; снимки `other-<телефон>-<демо>-0s.png`,
`layout FAIL` валит задание.

Два взгляда на кадр, и оба в логе:
- **цикл** (что контролирует приложение: главный поток — симуляция, ввод, HUD, звук): `fps`, `worst` в строках `hb`,
  `avgFps / minFps / worstFrame` в `demo done`, строки `hitch` (тик дольше 50 мс: `upd` — сцена + сборка мира,
  `draw` — всё после неё, в скобках по частям: `drawable` (ожидание drawable, ≤ 3 мс), `world` (проходы 1–3), `hud` (композит +
  `SKRenderer`; `cpu` — время процессора главного потока в нём: много меньше `hud` — поток ждал), `commit` (present + commit); `skip=a/b` — тиков без рисования: нет свободного слота / нет свободного
  drawable, `cb` — самый медленный недавний command buffer: коммит → готово, ожидание запуска, время GPU);
- **GPU и композитор** (что увидел экран): `drawn` (кадров, вернувшихся с GPU за секунду), `gap` (дольше всего на
  экране держалась одна картинка), `cbmax`, `gpumax`, `skip` (без слота), `nodraw` (без drawable), `drw` (самый долгий
  `nextDrawable()` в фоновой очереди; главный поток ждёт из него не больше 3 мс); в `demo done` — `drawnAvg / drawnMin / worstGap`.
  Если `cb` ≫ `gpu`, кадр ждал вне приложения: на раннерах GitHub это остановки GPU хоста симулятора (они есть и в
  `calm` без нагрузки).

`metrics.txt` (`ci/frame_metrics.py`) сводит это в таблицу; шаг «Frame metrics gate» — общий порог плана v2.0 для
каждого пакета: у тёплых демо 60 Гц средний fps цикла ≥ 59.5, минимальный ≥ 58, худший тик ≤ 43 мс и нет тиков
дольше 50 мс после первой секунды. Тик, в котором главный поток приложения сам работал < 10 мс, — остановка хоста
симулятора, а не подвисание: работа = `upd + draw` минус время, которое поток провёл вне CPU внутри `SKRenderer`
(`hud` − его `cpu`) и внутри кодирования мира (строка `metal: slow world encode N ms (thread cpu M ms)` — её пишет
`MetalRenderer` для кодирований дольше 2 мс; обычное — ≈ 0.2 мс; нет строки — значит, остаток `world` поток ждал в
`makeCommandBuffer`); такие тики идут в таблицу как `host-stalls`, не валят
порог худшего тика и подвисаний, а минимальный fps прогона, где были только они, держится на прежних 55. Тик 35–50 мс
(строки `hitch` у него нет; до 43 мс он влияет только на fps своей секунды, у меню 30 Гц — от 44 мс) — тоже остановка хоста, если максимумы самого приложения за ту секунду (`hb ms … max`,
время CPU самого долгого HUD `skcpu=`, ожидание drawable главным потоком — по устройству цикла не больше 3 мс,
кодирование мира > 2 мс) в сумме < 10 мс. `drawn` у `swarm3x` и
`release-combat` ≥ 55, а когда GPU хоста стоит сам (`calm` того же прогона без нагрузки < 57 кадров/с) — не меньше `calm` − 2.
Если демо не добирает средний / минимальный fps или кадры GPU, те же числа берутся ещё раз без секунд, где стоял хост
(тик-остановка хоста внутри секунды — ± 0.05 с: `td=` сердцебиения печатается с точностью 0.1 с, и тик, записанный в
`td=15.32`, принадлежит секунде, напечатанной как `td=15.3`; command buffer дольше 100 мс — в 10 с лишним раз дольше собственного времени GPU
самого медленного кадра), и проходят, если держатся на ≥ 4 чистых секундах и у демо нет подвисаний приложения (в строке
таблицы — пометка). У меню (`levelup` / `pause` /
`end`, 30 Гц) — только подвисания; у `firstlaunch` — худший тик ≤ 150 мс и доля рендерера в загрузке ≤ 0.5 с: сколько
сцена ждала фоновую подготовку Metal (`metal world ready in N ms`) за вычетом запуска службы компиляции шейдеров
симулятора (`first request N ms` сверх 0.3 с). Сама загрузка сравнивается с 1.6 с в отчёте и валит job только дальше
медианы тёплых + 2.5 с: на холодном запуске GPU хоста симулятора по нескольку секунд отдаёт ~5 кадров/с, пока заставка
ждёт свои 20 (тот же коммит `535ce21` в двух прогонах загрузился за 1.43 и 2.73 с; кадры GPU в секунду под заставкой
печатаются в строке); `drawn` ≥ 55 — только в `swarm3x` и `release-combat`
(остальная сторона GPU — в отчёт: хост симулятора останавливает GPU сам по себе, см. `calm`); медиана сглаженного
времени GPU кадра (`hb gpu … ema=`) ≤ 1.0 мс — сигнализация о патологиях, не бюджет; одно выделение цели мира на
запуск; прогон DRS (`probe`) — 10 шагов и ни одного тика дольше 34 мс по вине шага в секунды, где менялся масштаб: если
кадры той секунды на GPU быстрые (< 8 мс — цена шага на GPU была бы видна там), тик-простой хоста или тик короче 50 мс в
секунду, где максимумы работы приложения в сумме < 10 мс, — не шаг; из любого другого долгого тика сначала вычитаются
максимумы той секунды по разделам, которых шаг не касается (`sim`, `ev`, `cam`, `hud`, `au`, CPU отрисовки HUD,
ожидание drawable); остаток печатается как `step share`
(первое событие `telegraph.fill` в `probe` иногда стоит 16–61 мс в `ev` и попадает в секунду шага — это провал общих
правил, не DRS). Строки `hb ms` — разбивка тика по разделам (мс):
сцена (`sim`, `ev`, `cam`, `world`, `hud`, `au`) и мир (`cam`, `mar`, `bug`, `fx`, `up`). Ядро дополнительно гоняет
`swift test -c release --filter PerformanceTests` (строки `[perf]` в `core-perf.log`, на статус не влияет) и гейт
калибровки v1.1 `icehive-calib --preset gate --gate` (`calib.txt`, `calib.jsonl`; провал — строки `CALIB: FAILED …`, см.
«v1.1 «Ставки» — ядро»), справочно — сгенерированные станции (`calib-stations.txt`). Шаг
«Privacy manifest check» проверяет, что каждый API с обязательной причиной, который зовёт код (`systemUptime`,
`UserDefaults`, …), объявлен в `PrivacyInfo.xcprivacy`.

### WP5 «Эффекты» — частицы на GPU, выстрелы, взрывы, пятна, телеграфы

- **Частицы на GPU** (`FX/GPUParticles.swift`, `Shaders/Particles.metal`). CPU пишет только **записи эмиттеров**
  (144 байта: точка / кольцо, разброс, скорость, радиальная и сферическая скорость, жизнь, размер, цвет, гравитация,
  сопротивление, вид, задержка старта; одна запись — N частиц), поэтому его работа не растёт с числом частиц. Предпроход
  100: `fx_emit` раскладывает записи кадра по слотам кольца (хэш сида записи → разброс на GPU), `fx_sim` проходит все
  слоты: возраст, сопротивление, гравитация, палуба по сетке высот уровня 128² (искры, лёд, гильзы, обломки
  отскакивают, ихор прилипает, над бездной всё падает дальше), для «освещаемых» видов (дым, пар, обломки, ихор, гильзы)
  — свет в точке частицы: окружение + рассеяние четырёх фонарей с их куки + источники сетки WP2 (копия `LightBlock`

### История: SpriteKit или Metal

До 2.0 мир рисовался SpriteKit-спрайтами, пре-рендеренными из веб-версии (пять листов ≈ 14 МБ, ≈ 111 МБ после
декодирования). На ветке `native-metal` оба рендерера шли в CI на одних демо и сидах (симулятор iPhone 17 Pro,
коммиты 24e98d0 … db58a09): у Metal CPU 17–23 % против 31–38 % в `combat` и 20–22 % против 40–44 % с 1400 жуками,
вызовов 36–40 против 74–88, память 41–51 МБ против ≈ 138 МБ на пике загрузки, загрузка 0.9–1.4 с против 1.5–2.0 с,
и настоящее 3D, как в веб-версии. Остался Metal; SpriteKit-рендер мира, листы и их инструменты удалены (последний
коммит с ними — `db58a09`). Тогдашние провалы кадра в `beacon` (160–300 мс) оказались остановками GPU хоста
симулятора, а не работой приложения: у SpriteKit они были в той же доле (`sk=`), а у Metal главный поток ждал
свободный слот кадра внутри `update()` и замирал целиком — теперь он не ждёт никогда (см. «Как строится кадр»).
