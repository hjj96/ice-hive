# Бойцы отряда (WP4 «Отряд») — модели, скелет, клипы

Четыре бойца (`штурмовик`, `огнемётчик`, `криотехник`, `пулемётчик`) строятся процедурно в headless Blender и
отгружаются в `App/Resources/Characters/`:

| Файл | Что |
| --- | --- |
| `marine_<класс>.ihv` | IHV1 v2 со скиннингом (флаги 4 + 8): один меш 8–10 тыс. треугольников (броня, шлем, наплечники, ранец, оружие), общий скелет из 32 костей, 31 клип с дорожками (half4 поворот + half4 смещение на кость на кадр, 30 кадр/с), сокеты (дуло, фонарь, гильзы, рукояти с рамками кистей) |
| `marine_normal.iht` | массив из 4 слоёв (слой = класс), 1024², ASTC 6×6, касательные нормали, запечённые с high-poly |
| `marine_orm.iht` | массив из 4 слоёв, 1024², ASTC 6×6: AO (запекание), шероховатость, металл, иней (`paint.py`) |
| `marine_albedo.iht` | M2: массив из 4 слоёв, 1024², ASTC 8×8 sRGB: краска, акцент класса, сколы до грунта и стали, царапины, трафареты, грязь, иней (`paint.py`) |

```sh
tools/blender/build.sh                               # всё, включая бойцов (characters/build.sh), и гейты
BAKE_CHARACTERS=1 tools/blender/build.sh             # перезапечь карты бойцов (Cycles, ≈ 4 мин на класс) → characters/bake_src
venv/bin/python characters/readback_marines.py App/Resources/Characters OUT [sheet] [strips] [game] [details]
                                                     # лист моделей, полосы анимаций, игровая камера и крупные планы
                                                     # ИЗ ОТГРУЖЕННЫХ ФАЙЛОВ (Cycles)
venv/bin/python characters/preview_marines.py OUT.png [--classes assault] [--hi] [--views front,head,gun] [--pose stance]
                                                     # быстрый просмотр ИСХОДНИКА (без UV, запекания и экспорта, ≈ 30 с
                                                     # на класс): форма LOW или источник запекания HIGH с деталями
```

## Файлы

- `skeleton.py` — 32 кости (позы привязки — чистые смещения, A-поза рук 50°), кватернионы, FK, аналитический IK
  на 2 кости. Оружие держится **слева** (+x): ядро выпускает пули из точки «0,95 вперёд, 0,22 влево» (IceHiveCore
  `muzzlePosition`), дула всех четырёх стволов стоят там же (высота 1,10–1,22 м). Кость `ctrl` без вершин несёт
  кривые клипов: вес IK рук (оружейной и опорной), «стопа стоит» для обеих ног, свечение визора.
- `motion.py` — клипы из «описаний поз» (таз и грудь в пространстве модели, голова, оружие, цели IK кистей и стоп):
  стопы стоят на палубе и кисти лежат на рукоятях по построению. Ходьба и бег — параметрическая походка в 8
  направлениях (0 фазы — касание левой стопы, 0,5 — правой; таз проседает при касании, бег — с фазой полёта,
  пятка поднимается к отрыву, бёдра доворачиваются к движению, грудь держит прицел), стиль походки свой у класса.
  Рывок (присед → толчок → посадка → выпрямление, 4 направления), аддитивные «выстрел» (винтовка: отдача через
  корпус, плечи и ствол на каждый выстрел; ротор — дрожь; огнемёт — давление и раскачка; криолуч — гул) и
  «попадание» (спереди / сзади), «ранен» (колени → на колени → ничком), «ползёт» (петля 2 с), «подъём» (на
  четвереньки → на колено → в стойку; приложение проматывает его по прогрессу реанимации), «гибель» (судорога,
  оружие выскальзывает, визор гаснет). Гейты: скольжение стоящей стопы за шаг (0 по построению), ошибка IK (0).
- `mocap/` (сборка ощущений A1) — захват движения → клипы: `bvhsrc.py` (импорт BVH / glTF самим Blender'ом, позы в
  игровом пространстве), `rtg.py` (перенос на скелет: выравнивание покоя, масштаб по ноге, корень с постоянной
  скоростью, стойка класса, осанка, замыкание петли, растяжение шага, IK ног + замок стоп, подошва на палубе, оружие на
  груди и кисти на рукоятях IK рига, ctrl), `clips.py` (таблица: `idle` / `idle_b`, `walk_*` / `run_*` × 8, `turn_l` /
  `turn_r`; циклы и окна закреплены временами исходника), `cut.py` (нарезка используемых диапазонов в `sources/` +
  `SOURCES.md`: URL, лицензия, sha256, кадры). `motion.all_clips` берёт эти клипы, остальные — процедурные.
  `venv/bin/python -B characters/mocap/cut.py DL` — после правки таблиц (DL — оригиналы с именами `cmu_35_01.bvh`, …).
- `paint.py` (сборка ощущений M2) — материалы в пространстве текселей: карта позиций привязки (UV-треугольники LOD0 →
  позиция, нормаль, слот, кость на тексел) + каналы запекания (AO, сношенные фаски, маска покраски `MARK_*`) → альбедо
  (полевая серая матовая краска, цвет класса только на шлеме и верхе наплечников, сколы → грунт → сталь, царапины,
  грязь, потёки, сажа, прорезиненный подкостюм, иней), ORM (AO, шероховатость 0,6–0,8 краски / 0,86–0,93 ткани,
  металл, иней) и нормаль с зерном ткани, коркой инея и канавками царапин. Чистая функция numpy (хэш значений
  float32): md5 одинаков. Стенд: `venv/bin/python -B characters/paint.py App/Resources/Characters OUT [--classes …]`.
- `subd.py` — моделирование: клетки Catmull–Clark (модификатор Subdivision с заломами кромок), изогнутые секторные
  оболочки с завёрнутой внутрь кромкой (односторонние: изнутри их не видно), пластины / визоры / полосы,
  «прилепленные» к готовой поверхности лучами. Нормали вершин — numpy (у bmesh они между запусками не побитово
  одинаковы).
- `marines.py` — каталог деталей: общий корпус + у каждого класса свой шлем, наплечники, ранец и оружие; материалы,
  сокеты. Язык формы — силовая броня с гранёными пластинами:
  - **гранёные оболочки** (`arc_profile` / `loft_shell` / `limb_sections` / `ring_sections`): сечение пластины —
    ломаная с углами и килем по передней грани, сечения по длине конечности или вокруг корпуса, кромка завёрнута
    внутрь. Бедро (набедренник на переднюю и наружную стороны, с подсумком на ремнях у оружейной ноги), поножи с
    килем и раструбом над ботинком, налокотник и наколенник-щит с ребром (`shield_patch`), наплечные и предплечные
    оболочки, два сегмента брюшной брони поверх ребристого подкостюма, бёдерные пластины и набедренные щитки на
    поясе, тяжёлый ботинок (подъём, задник, щитки голеностопа, подошва из двух блоков);
  - **LOW уровня 0 там, где хватает плотной клетки** (`densify`): гладкость и фаски даёт запечённая нормаль от
    HIGH уровня 3, треугольники — силуэту (кираса, шлем, купол наплечника — уровень 1). 9,88–9,98 тыс. на класс;
  - **шлемы**: штурмовик — длинный красный шлем со стальным гребнем, шевронная лицевая пластина со светящейся «Т»,
    выступающая решётчатая челюсть, светлые нащёчники, блоки связи, назатыльник; огнемётчик — огнеупорный шлем с
    гребнем и козырьком поверх противогаза: круглые светящиеся линзы в стальных оправах, хобот респиратора с
    фильтром, боковые фильтры, тканевый назатыльник; криотехник — синяя задняя скорлупа, тёмный стеклянный купол
    со светящейся полосой и стальной дугой поверх, подбородник, охлаждающие блоки со стальными кольцами;
    пулемётчик — квадратный «топхельм» с фасками, стальной бровью над узкой светящейся щелью, ребром, решёткой с
    прорезями и болтами на нащёчниках;
  - **оружие — силуэты сбоку, выдавленные в толщину** (`gun_prism`): в LOW плоские грани, в HIGH все рёбра сняты фаской
    4 мм (запекаются как чёткие блики). Винтовка-буллпап (щека приклада, магазин за рукоятью, кожух с прорезями,
    дульный тормоз, коллиматор на планке, подствольник, ячейки питания), огнемёт «Факел» (короб, бак под стволом
    с бандажами, ствол в перфорированном теплозащитном кожухе, раструб сопла с запальником, манометр), криолуч
    (гранёный корпус с рёбрами радиатора, стеклянная колба, излучатель с тремя вращающимися катушками), ротор
    (корпус со скошенным носом, шесть стволов с хомутами, кожух над стволами, мотор, ручка сверху);
  - **детали только в HIGH** (уходят в карты): приподнятые подпанели (`panel`), жалюзи (`vents`), болты, рёбра
    подкостюма (`ribs`), ремни, трафареты — номера бойца семисегментными цифрами, шевроны, полосы опасности
    (`stencil`, `hazard`) в маске покраски;
  - **маска покраски**: `MARK_CLASS` (1) — цвет класса, `MARK_DARK` (0,5) — тёмный трафарет; размытая граница цвета
    класса проходит через тёмную полосу — тонкая окантовка, как у настоящей маркировки;
  - цвет класса — приглушённая полевая краска (M1 «без пластика»: `8e3228 / ac722a / 386a90 / 48763c`) на шлеме,
    наплечниках и ранце (видно сверху); пластины предплечий и наколенники — керамика корпуса (`118, 122, 123`, темнее и
    холоднее прежней), тёмный подкостюм, оружейный металл. Светятся только визоры, фонарь шлема и строб «свой — чужой»
    (слот `STROBE`, флаг вершины bit5: вспышка 70 мс цветом класса раз в 1,6 с, у каждого бойца своя фаза —
    `Characters.metal`) на ранце; прежние светящиеся полосы (наплечники, запястье, грудь, ранец, сопла, антенна, ячейки
    и катушки оружия, окна бака, кольца криотехника) — сталь, тёмная резина или тёмное стекло;
  - **пропорции** (`PROPORTION`, по классу, только вершины — скелет, клипы и кости сокетов прежние): шлем × 0,85–0,9
    вокруг шеи (кромка остаётся на воротнике, шея сужается вместе с ним), наплечники × 0,8 вокруг центра купола,
    купол площе (× 0,82–0,84 по высоте) и на 2–3 см ближе к шее, ранец и антенна × 0,9 вокруг крепления на спине (шланг
    к оружию тянется за ранцем только своей долей веса — его конец остаётся на оружии); сокеты `head_top` и `thrust`
    сдвинуты так же. LOW и HIGH проходят одно и то же преобразование — запекание следует за ним; кулаки ×1,12 (`skeleton.HAND_SCALE`, те же смещения
    рукоятей в `motion.grip_frames`); дула там, где ядро выпускает пули. Слот `HOT` (флаг вершины bit3): стволы,
    дульный тормоз, сопло, излучатель — в игре они раскаляются при долгой стрельбе (`Characters.metal`).
- `shapes.py` — общие примитивы (вращение, призма, фаска, болты, прорези).
- `build_marines.py` — сборка класса: объекты по областям, один UV-атлас, запекание (`--bake`) или чтение
  закоммиченного запекания (отпечаток геометрии и UV в `bake_src/bake.json`), экспорт вершин (MikkTSpace,
  v Metal сверху вниз), клипы, сокеты → IHV; массивы текстур → IHT; отчёт. Запекание идёт **группами деталей, не
  перекрывающих друг друга** (`bake_groups`: жадная раскраска по коробкам деталей +3 см): луч детали видит только
  её собственный HIGH и её детали-«поплавки» (`assign_floaters`: ближайшая деталь LOW), поэтому пластина больше не
  крадёт нормали соседней (вывернутые оливковые пятна старой карты) и AO не чернеет под чужой геометрией; в AO
  участвует весь HIGH (контактные тени между пластинами). Каждая группа — с полем 0, затем одно расширение островов
  по маске покрытия атласа (`dilate`).
- `readback_marines.py` — контрольные рендеры отгруженных файлов (позы — CPU-эталон скиннинга `ihv.skin_row`);
  полосы анимаций — каждый кадр своим тайлом со своей камерой и ключевым светом (≈ 400 px на бойца); `details` —
  крупные планы (шлем, оружие, корпус, ноги, спина).
- `preview_marines.py` — быстрый просмотр исходника каталога (LOW или HIGH с деталями, в стойке прицеливания)
  для работы над формой.

Гейты сборки (`reports/characters.json`): скольжение стоящей стопы за шаг (0 по построению; у клипов захвата — после
прохода замка), ошибка IK рук и ног (0), **касание** (`contact_m`: нижняя точка подошвы стоящей стопы на палубе, ≤ 5 мм) и
**пол**: самая низкая вершина каждого клипа (`floor_min_y_m`) — пластины лежащего / ползущего / встающего
бойца не уходят под палубу (стопы на коленях и ничком — носки подогнуты, колено ползущего уходит в сторону, а не в
пол).
